# .bin

`install.sh` でホームに `~/.bin` として symlink され、`.bashrc` の PATH 設定によって
どこからでもコマンドとして呼べるようになるスクリプト置き場。

新しくスクリプトを追加したら実行権限を付けること。

```bash
chmod +x .bin/<スクリプト名>
```

`.gitignore` はホワイトリスト方式だが、`!/.bin/` と `!/.bin/**` が既にあるので
このディレクトリ以下は追記なしでそのまま管理対象になる。

## 一覧

| コマンド | 概要 |
|---|---|
| [`install.sh`](#installsh) | dotfiles をホームに展開する |
| [`pdf2cbz`](#pdf2cbz) | PDF を CBZ（画像アーカイブ）に変換する |

---

## install.sh

dotfiles リポジトリ直下のドットファイル・ドットディレクトリを、ホームディレクトリへ
symlink として展開する。既存のファイルは `~/.dotbackup` へ退避される。

```bash
source ./.bin/install.sh
```

| オプション | 説明 |
|---|---|
| `-d`, `--debug` | 実行内容をトレースする |
| `-h`, `--help` | 使い方を表示する |

## pdf2cbz

PDF を CBZ に変換する。ディレクトリを渡すと配下の `*.pdf` を再帰的に処理し、
サブフォルダの構成は出力側にも再現される。

```bash
pdf2cbz [オプション] <PDF|ディレクトリ> [出力ディレクトリ]
```

出力ディレクトリを省略すると変換元と同じ場所に書き出す。詳細は `pdf2cbz --help`。

### なぜ CBZ にするのか

ebook サーバ（[shelf/Book](https://github.com/projects-shelf/Book) など）で漫画や
雑誌を読む場合、PDF はページを開くたびに描画処理が走るぶん重い。CBZ は中身が
ただの画像アーカイブなので、表紙の生成もページの表示も明確に速くなる。

実測（自炊 PDF 23冊・約1.5GB / WSL2）では、蔵書のスキャン時間が
1冊あたり 0.162 秒（PDF）から 0.036 秒（CBZ）へ短縮された。

### 2つの変換方式

| モード | 動作 | 画質 | 速度 |
|---|---|---|---|
| `extract` | 埋め込み画像をそのまま取り出す | 無劣化（再エンコードなし） | 速い |
| `render` | ページを画像として描画し直す | DPI と品質に依存 | 遅い |

既定の `auto` は、**1ページが1枚の画像でできている**「自炊」PDF なら `extract` を使い、
条件を満たさなければ `render` に自動で切り替える。スキャンした本はほぼ `extract` になる。

参考値（130ページの自炊コミック）:

| モード | 時間 | サイズ |
|---|---|---|
| `extract` | 3.0秒 | 66MB（元 PDF と同じ） |
| `render` | 18.4秒 | 100MB（再エンコードで膨張） |

### オプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `-m`, `--mode` | `auto` | `auto` / `extract` / `render` |
| `-r`, `--dpi` | `300` | `render` 時の解像度 |
| `-q`, `--quality` | `90` | `render` 時の JPEG 品質 (1-100) |
| `-i`, `--in-place` | — | 変換に成功した PDF を削除して置き換える |
| `-n`, `--dry-run` | — | 変換せず、対象と実行内容だけ表示する |
| `-f`, `--force` | — | 既に CBZ がある場合も上書きする（既定はスキップ） |
| `-h`, `--help` | — | ヘルプ |
| `-V`, `--version` | — | バージョン |

### 使用例

```bash
# 変換して元の PDF は残す（安全側。まずはこれ）
pdf2cbz ~/books

# 置き換える前に対象を確認する
pdf2cbz -n -i ~/books

# 変換して元の PDF を置き換える
pdf2cbz -i ~/books

# 別の場所に出力する（元のディレクトリは読み取りのみ）
pdf2cbz ~/books ~/books_cbz

# 解像度を下げて描画変換する（テキスト主体の PDF など）
pdf2cbz -m render -r 200 論文.pdf
```

### 実行環境

ホストに `poppler-utils` と `zip` があればそれを直接使う。無ければ Docker で
専用イメージ（`pdf2cbz-tools`）を**初回だけ**組み立てて使うため、事前の準備は要らない。
どちらも無い場合は導入方法を表示して終了する。

```bash
# ホスト側に入れておきたい場合
sudo apt install poppler-utils zip unzip   # Debian/Ubuntu
brew install poppler zip                   # macOS
```

### 安全性

`--in-place` は元ファイルを消すため、次の順序で確認してから削除する。

1. CBZ を生成する
2. **アーカイブ内の画像枚数と `pdfinfo` のページ数を照合する**
3. 一致した場合にのみ元の PDF を削除する

そのため、壊れた PDF・空ファイル・PDF を名乗る別形式のファイルは変換に失敗し、
**元ファイルはそのまま残る**。暗号化された PDF もスキップされる。

失敗した PDF が 1 件でもあれば終了コードは 1 になる。

### 実装上の注意点

将来いじるときに踏み抜きやすい箇所。

- **ページのファイル名はゼロ埋めで振り直している。** ビューアはアーカイブ内を
  単純な名前順で並べるものが多く（shelf/Book は Go の `sort.Strings`）、桁数が
  揃っていないと 1000 ページ超で `page10 < page9` となり順序が崩れる。
- **`pdfimages -all` は ccitt/jbig2 画像を「本体 + `.params`」の2ファイルで書き出す。**
  そのまま数えるとページ数と食い違い、ページ番号の対応がずれる。削除してから数えている。
- **ビューアが扱えない形式（`.ccitt` など）で出てきたページは描画し直して差し替える。**
  白紙ページが 1bit 画像で格納されている自炊 PDF で実際に起きる。放置するとその
  ページが丸ごと欠落する。
- **1ページに複数の画像がある PDF では `extract` を使わない。** 画像とページの対応が
  取れず順序を保証できないため、`auto` では `render` に落とす。
